
# Спецификация для ИИ: Реализация новых карт для режима «Восхождение»

## 1. Контекст и роль
Ты выступаешь в роли Senior 1C-Разработчика. Твоя задача — реализовать 21 новую карту для roguelike-режима «Восхождение» в проекте Veritas (1С:Предприятие 8.3.26+, мобильная платформа, управляемые формы). 
Проект представляет собой тренажер-викторину, где правильные ответы позволяют разыгрывать карты, а ошибки активируют действия противника.

Перед началом работы ты обязан изучить следующие файлы из базы знаний:
- `QWEN.md` — архитектура проекта и структура репозитория.
- `game_design.md` — механики, параметры игрока/противника, зоны карт.
- `project-map.md` — карта путей к модулям (используй для поиска файлов).
- `AI_RULES.md` — строгие стандарты написания кода на 1С (BSL).

## 2. Точки входа и архитектура
Реализация карт затрагивает следующие объекты конфигурации:
1. **Справочник `Карты`**: Все предопределнные элементы уже добавлены. Если какого-то не хватает - спроси пользователя.
2. **Основной движок боя**: Модуль формы `DataProcessors/ТестированиеЗнаний/Forms/Форма/Ext/Form/Module.bsl`. 
   - Каждая карта должна получить собственный обработчик в формате `ДействиеКарты_<ИмяКарты>`.
   - Диспетчеризация вызовов происходит в процедуре `ДействиеВыбраннойКарты()`.
3. **Новые механики**: Для карт с эффектами «Изгнание» потребуется расширить базовые процедуры удаления карт из колоды.

## 3. Строгие правила кода (из AI_RULES.md)
При генерации кода ты обязан неукоснительно соблюдать следующие требования:
- **Форматирование**: Запрещены пустые строки внутри тела метода. Логические блоки разделяются комментариями-заголовками (например, `// Инициализация.`).
- **Атомарность**: Одна строка — одно действие. Запрещены составные выражения (например, `Возврат НЕ Запрос.Выполнить().Пустой();` недопустим).
- **Ветвление**: Каждый `Если` обязан иметь блок `Иначе`. Если действий нет, пишется поясняющий комментарий.
- **Именование**: 
  - Переменные: CamelCase/PascalCase. Для итераторов префикс `Тек`.
  - Параметры: `Вход` (неизменяемые), `Изм` (изменяемые).
  - Булевы: начинаются с `Это`, `Есть`, `Разрешено`.
  - Функции/Процедуры: `Глагол + Существительное`.
  - Возврат функций: через переменную `РезультатФункции`.
- **Обработка ошибок**: Запрещён `ВызватьИсключение` в бизнес-логике. Использовать флаги (`ЕстьОшибки`). Запись в БД только через `Попытка...Исключение` с выводом `КраткоеПредставлениеОшибки(ИнформацияОбОшибке())`.
- **Локализация и UI**: Все строки для пользователя через `НСтр("ru = '...'")`. Вывод сообщений через `Сообщить()`.

## 4. Описание новых механик
Для реализации списка карт необходимо внедрить или проверить следующие подсистемы:

### 4.1. Механика «Изгнание» (Уход из колоды)
Карта `Последний довод` может навсегда покинуть колоду в текущем бою.
- Реализуй процедуру `ИзгнатьКарту(ИмяКарты)`, которая удаляет карту из `РукаИгрока`, `СтопкаДобора` и `СтопкаСброса` на время текущего боя (или перемещает в невидимую стопку изгнанных).

### 4.2. Мгновенный розыгрыш без затрат энергии
Карта `Переоценка ценностей` требует разыграть другую карту бесплатно.
- Реализуй функцию `НайтиСамуюДорогуюКартуВРуке()`.
- При розыгрыше временно переопредели логику проверки энергии или вызови `ДействиеВыбраннойКарты()` с флагом игнорирования стоимости, после чего сброси сыгранную карту.

## 6. Пошаговый алгоритм для нейросети
1. **Анализ контекста**: Изучи `DataProcessors/ТестированиеЗнаний/Forms/Форма/Ext/Form/Module.bsl`. Найди процедуры работы с рукой (`РукаИгрока`), сбросом (`СтопкаСброса`), параметрами игрока и противника.
2. **Подготовка механик**: 
   - Реализуй или доработай диспетчер `ПриСбросеКарты`.
   - Реализуй функцию изгнания карт из колоды.
   - Реализуй функцию поиска самой дорогой карты в руке.
3. **Наполнение предопределённых данных**: Добавь записи для 21 новой карты в структуру справочника `Карты` (учти атрибуты `Описание`, `Стоимость`, `Открыта`).
4. **Реализация обработчиков**: Для каждой карты создай процедуру `ДействиеКарты_<Имя>` в модуле формы. 
   - Строго соблюдай правило «Одна строка — одно действие».
   - Инициализируй все константы и перечисления в начале метода с комментарием `// Инициализация.`.
   - Используй `НСтр()` для любых текстовых выводов.
5. **Интеграция**: Подключи новые обработчики в главную процедуру розыгрыша карт `ДействиеВыбраннойКарты()`.
6. **Проверка на стандарты**: Убедись, что в коде нет пустых строк внутри методов, все `Если` имеют `Иначе`, нет вызовов `ВызватьИсключение`, а запросы к БД (если они потребуются) не находятся внутри циклов.
